# GraphQL client (= `@affine/graphql`, `packages/common/graphql`)

**One sentence:** the typed, generated frontend SDK for the server's GraphQL API — `.gql` documents, fetcher wiring, and the schema types checked into source control.

## Why this shape

The server exposes one GraphQL endpoint (`packages/backend/server/src/schema.gql`). Instead of hand-writing queries across packages, documents live as `.gql` files here (`src/graphql/admin/*.gql`, etc.) with generated types (`src/schema.ts`), giving every caller end-to-end typed queries and one place to regenerate when the server schema changes.

## Shape

- `packages/common/graphql/src/graphql/**/*.gql` — query/mutation documents grouped by domain (admin, …).
- `src/fetcher.ts` — transport (fetch + auth handling).
- `src/schema.ts` — generated types mirroring the server SDL.

## Connected to

- mirrors: `objects/backend-server/server-core.md` GQL resolvers (schema.gql is the contract between them).
- consumed-by: `@affine/core` cloud/account features, admin app, e2e fixtures.
- looks-like-but-is-not: not the server itself; changing `.gql` files here does not change the API.

## If you change this

Hits: every caller of the affected query/mutation; codegen outputs (`schema.ts`).
Does not hit: resolver behavior — regenerate from the server after changing resolvers there instead.

## Surfaces

Consumed at build time (codegen) and runtime (fetcher); regenerated by humans after server schema edits.
